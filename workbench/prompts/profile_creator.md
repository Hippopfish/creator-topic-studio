你在给这个账号写第一版**长期运营规划**（CreatorProfile）。它以后要用于选题、写稿和复盘，所以每个判断都要有依据。

【账号】{{accountName}}｜目录 {{nCatalog}} 篇｜今天：{{today}}

【目录统计】
{{catalogFacts}}

【全部目录】
{{catalogTable}}

【深读正文】
{{deepBodies}}

【已分出的内容类型】
{{typeList}}

【上一版规划】（有就保留仍有效的部分，只合并这次的变化）
{{existing}}

【要求】
1. 分三层写清楚：**已确认事实**（有数据或正文支撑）、**规划建议**（你提的，还没被认可）、**待确认**（缺证据的）。
2. 不要只把历史内容归类。方向要解释价值和边界；栏目要说明怎么持续产出，并给代表性选题例子。
3. 表现规律只能用目录数据算出来的东西说话（哪个形式赞中位高、哪类内容收藏高），**不许把点赞推算成曝光、播放、完播或涨粉**。
4. 更新节奏写实际的（间隔中位数、每周几篇），不写「保持稳定更新」这种空话。
5. 建议的栏目名称不等于已确认的公开身份，要标出来。
6. 缺证据的地方写进 unknown，不要留「待补充」这种占位符。
7. **「表现规律」里的每个数字都必须来自上面的【目录统计】，原样引用，不要自己重新算中位数、比例或倍数。**统计里没给的项，就不要写数字，宁可不提。
8. markdown 正文里如果提到具体数字，同样必须和【目录统计】完全一致；拿不准就把那句改成定性描述（「多图表现更好」），不要写一个凭印象的数字。

【输出 JSON】
{
  "markdown": "完整的规划正文，用 markdown，包含：定位与受众 / 长期目标 / 内容方向及价值 / 栏目规划 / 内容配比 / 更新节奏 / 阶段重点与复盘调整 / 待确认",
  "fields": {
    "positioning": "一句话定位（会用于选题判断）",
    "audience": "目标读者是谁、他们关心什么（会用于选题判断）",
    "pillars": ["内容支柱，3-5 个短词"],
    "cadence": "更新节奏，一句话",
    "goal": "当前阶段的主要目标，一句话",
    "performance": ["表现规律，一行一条，带数字"]
  },
  "unknown": ["哪些项缺证据，没法判断"]
}

markdown 里不要出现「test」「placeholder」「TODO」「待补充」。只输出 JSON。
